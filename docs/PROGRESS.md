# Progress Log

Update at the end of every stage. Two minutes each time. This file is what the
final report's "what was built" section gets written from, and it is the fastest
way for anyone (including a future you, or an agent) to know the real state of
the repo rather than the planned one.

Format per entry: what works, what is knowingly broken, what was skipped and why.
Be honest about the broken parts — an acknowledged limitation reads better than
an unnoticed one.

## Stage 0 — Foundations
**Status:** done

- Works: `docker compose up -d` (postgres 18 + pgvector 0.8.6, redis 7); FastAPI
  skeleton with `/health` checking both; Alembic wired against `app.db.Base`
  with an empty baseline migration applied; `ruff` clean; one smoke test
  (`/health` returns 200) passing; `Makefile` targets `up/migrate/seed/dev/demo/eval/test/lint`.
- Known broken: none.
- Skipped: `make demo`/`make seed` are stubs until Stage 1 (`app.seed.run`
  does not exist yet) and Stage 6 (no scripted scenario yet).
- Notes:
  - Toolchain: Python 3.13 via `uv` (system only has 3.10-3.12), deps managed
    with `uv pip install -e .` into `backend/.venv`. `pnpm` for the frontend
    later.
  - Host ports 5432/5433 were already taken by other local projects
    (`paintkart-postgres`, `agentrail-postgres`) — this project's Postgres is
    remapped to host port **5434** in `docker-compose.yml` and `.env`. Redis
    stayed on the default 6379.
  - `pgvector/pgvector:pg18` changed its volume convention vs. earlier images:
    it expects a single mount at `/var/lib/postgresql`, not
    `/var/lib/postgresql/data` — mounting at the old path crashes the
    container on startup with a `pg_ctlcluster`-format error. Fixed in
    `docker-compose.yml`.
  - `.env` lives at the repo root, not `backend/`, so `app/config.py`
    resolves `_REPO_ROOT_ENV` relative to the file's own location rather than
    cwd — otherwise `alembic` (run from `backend/`) silently falls back to
    default settings and connects to the wrong Postgres.

## Stage 1 — Data model and seed
**Status:** done

- Works: all 19 tables from `03-data-model.md` as SQLAlchemy 2.0 models
  (`app/models/{support,commerce,kb,escalation,observability}.py`), applied via
  one autogenerated Alembic migration; `pgvector` HNSW index and the generated
  `tsv` GIN index confirmed present on `kb_chunks`. `core/tickets.py` validated
  status transitions with 74 tests (every legal + every illegal transition).
  `core/identity.py` + `core/conversation.py` + `ingress/pipeline.py` do
  identity resolution, conversation threading and ticket opening, exercised by
  `POST /dev/simulate/web` and 3 ingress tests (create, dedupe, thread
  continuity). Seed script (`app/seed/run.py`, fixed seed `20260908`,
  idempotent via `TRUNCATE ... RESTART IDENTITY CASCADE`) loads 95 customers,
  200 orders, 233 transactions, 2 refunds, 8 KB documents, 4 human agents.
  78 tests passing, ruff clean.
- Known broken: none.
- Skipped: KB chunking/embedding (`kb_chunks` stays empty until Stage 3's RAG
  ingestion step runs against `kb_documents`) — deliberate, not an oversight.
- Notes:
  - **10 hand-written order edge cases**, not the ~35 the data-model doc
    describes: delivered-but-claimed-missing, stuck-past-ETA, cancelled-after-
    ship, duplicate-charge, partial-return (mixed returnable items), COD
    refund, out-of-window return, cancellable-now, out-for-delivery-today,
    failed-payment-never-placed. Each is a distinct scenario shape rather than
    a volume target; more can be added organically as the eval dataset grows
    in Stage 11 if a scenario is missing. Flagging this now so it's a visible
    scope call, not a silently smaller dataset.
  - Two real bugs the tests caught before they became demo failures:
    1. `Mapped[datetime]` columns defaulted to `TIMESTAMP WITHOUT TIME ZONE`,
       not `timestamptz` as the schema doc requires — `transition_ticket()`
       assigning `datetime.now(UTC)` then crashed on
       "can't subtract offset-naive and offset-aware datetimes". Fixed with a
       `type_annotation_map = {datetime: DateTime(timezone=True)}` on `Base`
       (`app/db/session.py`) rather than annotating every column by hand.
    2. Async SQLAlchemy: once an object has been `flush()`-ed, touching an
       *unset* relationship attribute (e.g. `conversation.ticket`) triggers an
       async lazy-load, which raises `MissingGreenlet` outside a greenlet
       context — it doesn't matter that the object was created in the same
       request. Fixed by querying explicitly (`select(Ticket).where(...)`)
       instead of reading the relationship, and by assigning relationship
       *objects* (`Message(conversation=conversation, ...)`) rather than only
       FK ids when the caller needs to read that relationship back.
  - Also dropped an initial dedupe implementation that caught the UNIQUE
    constraint's `IntegrityError` inside a `begin_nested()` savepoint — worked
    in tests (which already run inside a savepoint-joined session) but broke
    against the real `async_sessionmaker` session used by the API, leaving the
    session in `PendingRollbackError` on the next `commit()`. Replaced with a
    plain `SELECT` before insert. Simpler, and correct for the actual case
    (webhook retries, not sub-millisecond races) — the UNIQUE constraint stays
    as the backstop for a true concurrent-delivery race, which is rare enough
    to accept as a 500 per prototype tolerance rather than engineer around.
  - Test isolation: one connection per test wrapped in a rolled-back
    transaction (`join_transaction_mode="create_savepoint"`), run against the
    real dev Postgres rather than testcontainers or a separate test DB — see
    `docs/decisions/0003-prototype-scope.md`. Needed an autouse
    `engine.dispose()` fixture: pytest-asyncio gives each test its own event
    loop, but asyncpg connections are bound to whichever loop created them, so
    without disposing the pool between tests, the second test in a session
    intermittently fails trying to use a connection tied to an already-closed
    loop.
  - `pgvector`'s Alembic autogenerate renders `pgvector.sqlalchemy.vector.VECTOR(...)`
    but does not add the corresponding `import pgvector.sqlalchemy` to the
    migration header — added by hand both times; check for this on every
    future autogenerate that touches `kb_chunks`.
  - `.env` needs `POSTGRES_PASSWORD`/`CREATE EXTENSION citext` for
    case-insensitive email columns; `make up` now creates both `vector` and
    `citext` extensions.
